# 当前存档难度切换可行性（2026-11-14）

## 已核对的原生行为

- `Msg/CNzh/System_Hub.msbt.zst` 包含「更改难度」「降低游戏的难度」和「仅可更改为较低的难度，若想提高难度，需执行再次降临」。游戏已支持当前存档降难度。
- 更新 `131072` 的原生 `main`：`main+0x169ba34..0x169ba74` 读取游戏状态对象 `main+0x220ab10` 指向的字节 `+0x0d`，值为 `0/1/2`（普通／困难／超难）。原生降低流程以当前值减一作为目标。`main+0x169c030..0x169c044` 的原生方法将目标值写回同一字节。
- `main+0x6def90..0x6defac` 读取每个单位 `+0x270` 的难度索引，用于选择人物表的难度能力补正。因此切换全局值并不等于重算当前战斗里已经生成的单位。
- 模式字节位于同一对象的 `+0x0c`，`0/1` 分别对应轻松／经典。原生存档界面从这里读取模式。

## 安全的实现边界

1. 在据点因果祭坛的原生「更改难度」后提供普通／困难／超难，再进入轻松／经典二级菜单；沿用游戏状态字段及原生保存流程。F1 → Core mods 的 `difficulty_switch` 开关默认关闭，重启后生效。
2. 进入战斗后不允许直接切换。新值从下一次构建战斗单位时使用；对现有战斗单位和已经结算的进度不回算。
3. 确认选择需再次点击同一模式，随后在游戏里保存。更换经典／轻松只改变之后的阵亡规则；既有永久阵亡人物不复活。
4. 先在隔离存档实测普通→困难、困难→超难、超难→困难，以及两种模式切换；核对退出重进后的字段和新战斗的敌方等级／能力、阵亡行为。未经这些测试，不宣称双向切换已经可用。

## 当前结论

已加入两层原生样式菜单和开关，运行库编译通过。用户已在游戏内验证菜单显示、普通／轻松改为超难／经典、读档后祭坛显示超难／经典，以及保存预览的「超难」文字。自定义存档栏位已实测分别显示普通／轻松、超难／经典。切换后下一场战斗的敌方数据与阵亡结算仍待验证；在此前按测试候选功能处理。
